Setup & Test Guide
Prerequisites
·Chrome, Edge, or Opera — Firefox and Safari do not support WebHID
·Page must be on localhost or HTTPS (secure context required)
·KioskDongle connected to this computer via USB-C
Connecting
1.Plug the KioskDongle into a USB-C port on this computer
2.Click Try WebHID in the status bar — the amber glow indicates it is available
3.Select KioskDongle in the browser device chooser and click Connect
4.The device name turns green and live stats appear — you are connected
Verifying Data Flow
·RX (Reticulum → kiosk): Gateway KiB/s shows non-zero when Reticulum sends data
·TX (kiosk → Reticulum): HID rpt/s goes non-zero; client app status bar turns green
·Green RX bars and blue TX bars in the right sidebar animate on traffic
Peer Link Modes
BLE Dongle relays via Bluetooth LE to the client laptop. Run: python main.py --uplink ble --mode webhid
Wi‑Fi Dongle hosts its own AP — no laptop needed. Set SSID & password above, click Apply + Reboot, then connect to the dongle's Wi-Fi AP and run: python main.py --uplink none
Troubleshooting
·Button greyed out — browser lacks WebHID support. Use Chrome or Edge on desktop.
·Empty device chooser — check USB cable; try unplugging and reconnecting the dongle.
·Stats stuck at zero — confirm Reticulum is running and the client app is up on port 4243.
·Device keeps disconnecting — use a direct USB port; powered hubs can drop vendor HID devices.
⚠ This mode is experimental. Data loss may occur under heavy load or marginal BLE links. Standard QR mode remains available at any time via ← Standard.
